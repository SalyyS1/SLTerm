## 2. Structural findings that shape build cost

1. **Three dead seams already exist and are cheap to revive.** `NotifyCommand` (RPC + Electron handler, no callers), `MonacoDiffViewer`/`DiffViewer` (component, no callers), and `cmd:interactive`/`cmd:login` (meta keys, no readers). Notifications and diff review are therefore "wire it up", not "build it".
2. **No action registry anywhere.** Every global action is an anonymous closure in `globalKeyMap` (`frontend/app/store/keymodel.ts:396-566`). Rows 11 (palette) and 20 (keybindings) share one prerequisite: give actions ids + labels and a lookup table. Build them together or pay twice.
3. **`pkg/aitools` is the template for every new Go capability.** ~200 LOC, path-segment validation (`aitools.go:87`), scope split, warnings channel, 4 RPCs, a 213-LOC React view. `pkg/agentteams` repeats the same shape. Any new pkg (vcs, claudesession, prompts) should clone it.
4. **Widget registration is data, not code.** A new capability reaches the user by adding one `defwidget@x` entry to `pkg/wconfig/defaultconfig/widgets.json` plus a `view:x` case in the block-view switch. There is also a live widgets editor (`frontend/app/view/waveconfig/widgets-editor.tsx`, 764 LOC).
5. **Workspace is the wrong abstraction for "project".** `waveobj.Workspace` (`pkg/waveobj/wtype.go:174-183`) carries no path. Every directory-scoped capability (git, worktrees, global search, project-scope aitools) currently has to re-derive a project root per block. Adding one `projectdir` field is the shared unlock.
6. **Block job status is the only liveness channel and it is process-level.** `BlockJobStatusData` (`pkg/wshrpc/wshrpctypes.go:887-897`) + `block:jobstatus` events. Agent-level state must be derived elsewhere (transcript tailing or output heuristics) — it is not a field you can just start setting.
7. **Scrollback is circular and capped** (`pkg/blockcontroller/shellcontroller.go:393`), so it can never serve as session history. History needs its own store.

Open questions for the plan:
1. `cmd:interactive` and `cmd:login` are declared meta keys with no Go reader (`pkg/waveobj/metaconsts.go:42-43`). Were they intended to force a login shell / allocate a PTY differently, or are they leftovers to delete? Both agent widgets set them today, so the widgets promise behaviour that does not exist.
2. Agent state (item 8) can come from tailing the session JSONL (accurate, couples SLTerm to Claude's on-disk format) or from terminal-output heuristics (format-independent, fragile, works for Codex too). This fork drives whether `pkg/claudesession` becomes a hard dependency of the agents dashboard.
3. `pkg/agentteams` reads `~/.claude/tasks/<team>/*.json` (`agentteams.go:113`) and `~/.claude/teams` does not exist on this machine — so the team-roster half of row 6 is currently unexercised. Confirm the directory contract before building mutation on top of it.
4. Does "project" become a first-class object or just a field on `Workspace` (item 4)? A field is far cheaper; a separate object is needed if one workspace should hold several repos.
5. Notifications (item 1) need an owner for the *decision* to notify. Under the zero-logic rule the Rust shell only renders it — but the trigger could sit in Go (`jobmanager`) or React. Go is the better fit for headless/remote cases; confirm.
